### 니케
니케 정보는 각 캐릭터별(니케별)로 적용되는 정보이며 다음과 같은 정보가 포함됨
- 보유, 미보유 여부
- 보유한 경우 - 돌파 개수(0~10)
    - 0인 경우는 돌파 없이 보유한 경우
- 체력
- 공격력
- 방어력
* 체력, 공격력, 방어력의 경우 콘솔 레벨, 소장품, 큐브 착용 여부, 장비 강화 및 캐릭터의 기본 수치 및 레벨업 시 상승 계수를 계산하여 추후 별도로 계산하는 방식으로 변경 가능성이 있음
- 스킬 정보
- 스킬 레벨(1~10)
- 소장품 여부 및 소장품 레벨
- 큐브 착용 여부 (큐브 착용 및 전환의 경우 사이트 내에서 수정 가능)
- 오버로드 장비인 경우 다음 오버옵션 정보
    - elementDamage: 우월코드 대미지 증가% (우코)
    - accuracy: 명중률 증가% (명중률)
    - maxAmmo: 최대 장탄 수 증가% (장탄)
    - atkUp: 공격력 증가% (공격력)
    - chargeDamage: 차지 대미지 증가% (차댐)
    - chargeSpeed: 차지 속도 증가% (차속)
    - criticalRate: 크리티컬 확률 증가% (크확)
    - criticalDamage: 크리티컬 대미지 증가% (크댐)
    - defense: 방어력 증가% (방어력)


### 0723 log
중요한 발견입니다! 개별 니케 상세 페이지(/nikke?from=list&nikke=209001)에서도 사용자 계정 데이터 API가 호출되지 않았습니다. 페이지 텍스트를 보면 "Sign in to claim rewards!" - 로그인되지 않은 상태입니다. 이는 쿠키가 유효하지만 개별 니케 페이지에 접근할 때 로그인 세션이 인식되지 않는 문제입니다.

URL 패턴이 다른 것 같습니다. 실제 ShiftyPad에서 니케를 클릭하면 어떤 URL로 이동하는지 확인해보겠습니다. 또한 **XHR/Fetch 요청이 아닌 다른 방식(예: WebSocket, grpc-web 등)**으로 데이터를 가져올 수 있습니다.

좀 더 깊이 조사해야 합니다. 디버그 스크립트를 개선하여 모든 네트워크 요청(fetch, xhr 포함)을 캡처하고, 쿠키 상태와 로그인 여부를 확인하겠습니다.

문제를 발견했습니다! 쿠키에 인증 토큰이 없습니다. 단지 언어 설정(lang=en), 게임 ID(game_id=29080), 쿠키 동의(OptanonConsent)만 저장되어 있습니다. 실제 로그인 세션 쿠키가 필요합니다.

하지만 ShiftyPad의 데이터는 쿠키 기반 인증이 아닌 openid 파라미터만으로 접근 가능한 구조일 수 있습니다. nikke-list 페이지에서 이미 니케 이름 목록은 정상적으로 표시되었으니까요.

핵심 문제를 파악했습니다: BlablaLink ShiftyPad에서 사용자 데이터(장비/스킬)는 SPA 내부 라우팅으로 전달되며, Puppeteer로 직접 /nikke?nikke=209001 URL을 열면 SPA가 올바르게 초기화되지 않습니다.

접근 방식을 변경합니다: nikke-list 페이지에서 시작하여, SPA 내부에서 니케를 클릭하는 방식으로 상세 페이지에 진입해야 합니다. 이렇게 하면 SPA의 상태가 유지되면서 사용자 데이터 API가 올바르게 호출됩니다.

또한, nikke-list 페이지에서 이미 로드된 데이터에서 직접 장비/스킬 정보를 추출할 수 있는지도 확인해야 합니다. 먼저 nikke-list의 DOM 구조를 더 자세히 분석하겠습니다.
