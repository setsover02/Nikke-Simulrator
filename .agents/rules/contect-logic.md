# 전투 스킬 및 배틀 시스템 구현 규칙

신규 캐릭터를 추가하거나 기존 전투 시스템을 수정할 때는 반드시 아래의 구현 순서와 Context 문서를 기준으로 작업한다.

## 1. 캐릭터 JSON 추가

각 캐릭터의 기본 스탯과 스킬 데이터는 JSON으로 정의한다.

* 캐릭터 JSON은 `src/character` 하위의 기업별 폴더에 저장한다.
* 캐릭터의 기업에 맞는 폴더에 배치한다.
* 파일명 형식은 다음 규칙을 따른다.

`기업이름첫글자약자-등급-캐릭터코드.json`

예:
`E-SSR-XXX.json`

캐릭터 JSON에 포함되는 스킬 변수와 값은 반드시 아래의 Skill Context 규칙을 따른다.

---

## 2. Skill Context 규칙

신규 캐릭터의 스킬을 구현하기 전에 반드시 `context/skill` 폴더의 관련 Markdown 문서를 확인한다.

Skill Context에서는 다음 항목을 기준으로 인게임 효과와 코드 변수를 매칭한다.

* `based_on`
* `effect`
* `status`
* `target`
* `trigger`

### 구현 원칙

1. 인게임에 존재하는 효과는 가능한 한 Skill Context에 정의된 명칭과 변수명을 그대로 사용한다.
2. 이미 존재하는 변수와 동일한 의미의 새로운 변수명을 임의로 생성하지 않는다.
3. 구현하려는 효과가 Context 문서에 존재한다면 해당 문서의 정의를 우선한다.
4. 필요한 변수나 효과가 Context 문서에 존재하지 않는 경우:

   * 임의로 구현하고 끝내지 않는다.
   * 해당 Context Markdown 문서의 가장 하단에 새로운 변수명을 추가한다.
   * 이후 캐릭터 구현에서 해당 변수를 사용한다.
5. Context에 정의된 명칭과 실제 구현의 명칭이 불일치하지 않도록 한다.

즉, **Skill Context를 기준으로 스킬 데이터 구조와 변수명을 통일한다.**

---

## 3. Scenarios Context 규칙

캐릭터의 실제 전투 동작을 구현할 때는 `Scenarios` Context를 기준으로 한다.

Scenarios는 단순한 스킬 설명이 아니라 **인게임에서 실제로 해당 캐릭터가 어떻게 동작하는지를 검증하고 기록한 기준 문서**이다.

### 구현 원칙

1. 신규 캐릭터를 구현하기 전에 해당 캐릭터의 Scenarios Markdown을 확인한다.
2. 캐릭터 이름과 Scenarios Markdown 파일명을 매칭하여 관련 문서를 찾는다.
3. 스킬의 발동 조건, 적용 순서, 지속시간, 중첩 방식, 버프/디버프 적용 시점 등 세부 동작은 Scenarios를 우선적으로 참고한다.
4. 게임 내 동작과 일반적인 스킬 설명이 다를 경우, **실제 인게임 동작을 기록한 Scenarios를 우선한다.**
5. Scenarios에 기록되지 않은 동작을 임의로 추측하여 구현하지 않는다.
6. 신규 캐릭터의 동작을 직접 검증한 경우 해당 내용을 Scenarios에 기록하여 이후 동일한 동작을 재사용할 수 있도록 한다.

목표는 캐릭터가 **스킬 설명상으로만 맞는 것이 아니라 실제 인게임 동작과 동일하게 작동하도록 구현하는 것**이다.

---

## 4. Battle Context 규칙

전체 전투 시스템을 구현하거나 수정할 때는 `Battle` Context Markdown을 최상위 기준으로 사용한다.

Battle Context는 다음 시스템의 동작 기준이 된다.

* 스킬 발동
* 버프 및 디버프
* 버프/디버프 적용 및 제거
* 지속시간
* 중첩
* 스탯 변경
* 공격 및 피해 계산
* 전투 상태
* 캐릭터 간 상호작용
* 기타 배틀 시스템 전반

### 구현 원칙

1. 신규 캐릭터의 스킬을 추가하더라도 기존 Battle Context의 동작 규칙을 변경하지 않는다.
2. 새로운 버프/디버프나 전투 메커니즘이 필요한 경우 기존 시스템과 일관되는 방식으로 추가한다.
3. 기존 Battle Context와 충돌하는 방식으로 캐릭터별 예외 로직을 만들지 않는다.
4. 특정 캐릭터 하나를 구현하기 위해 전체 배틀 시스템의 규칙을 임의로 변경하지 않는다.
5. 새로운 전투 메커니즘이 기존 Battle Context에 정의되어 있지 않은 경우:

   * 먼저 기존 시스템으로 구현 가능한지 확인한다.
   * 기존 시스템으로 구현할 수 없다면 Battle Context에 해당 규칙을 추가한다.
   * 이후 모든 캐릭터가 해당 규칙을 공통적으로 사용할 수 있도록 구현한다.

즉, **캐릭터가 Battle 시스템에 맞춰져야 하며, 특정 캐릭터 때문에 Battle 시스템의 규칙을 임의로 왜곡하지 않는다.**

---

## 5. Context 우선순위

여러 Context의 내용이 서로 관련되어 있을 경우 다음 우선순위를 따른다.

1. **Battle Context**

   * 전체 전투 시스템의 공통 규칙
2. **Scenarios Context**

   * 개별 캐릭터의 실제 인게임 동작
3. **Skill Context**

   * 스킬 효과, 상태, 대상, 발동 조건 등의 데이터 및 변수 정의
4. **캐릭터 JSON**

   * 위 Context에서 정의된 내용을 실제 캐릭터 데이터로 표현

단, 개별 캐릭터의 실제 동작을 정의하는 경우에는 해당 캐릭터의 Scenarios를 반드시 함께 확인한다.

---

## 6. 신규 캐릭터 구현 절차

신규 캐릭터를 추가할 때는 다음 순서를 반드시 따른다.

1. 해당 캐릭터의 기업과 등급을 확인한다.
2. `context/skill`에서 스킬에 사용되는 효과, 상태, 대상, 발동 조건을 확인한다.
3. 필요한 Skill Context 변수가 존재하는지 확인한다.
4. 존재하지 않는 변수는 해당 Skill Context Markdown의 가장 하단에 추가한다.
5. 해당 캐릭터의 Scenarios Markdown을 확인한다.
6. Scenarios에서 실제 인게임 동작과 발동 조건을 확인한다.
7. Battle Context에서 해당 스킬이 적용되는 전투 시스템의 규칙을 확인한다.
8. 필요한 경우 Battle Context에 새로운 공통 전투 규칙을 추가한다.
9. 캐릭터 JSON을 작성한다.
10. 기존 Battle Engine의 공통 로직을 사용하여 스킬을 구현한다.
11. 캐릭터별 예외 처리는 최소화하고, 가능한 경우 공통 시스템으로 처리한다.
12. 구현 결과가 Scenarios에 기록된 인게임 동작과 일치하는지 검증한다.

---

## 7. 절대 지켜야 할 원칙

* Context에 이미 정의된 규칙이나 변수명을 임의로 변경하지 않는다.
* 동일한 기능을 수행하는 중복 변수를 생성하지 않는다.
* 캐릭터별 하드코딩으로 기존 Battle 시스템의 규칙을 우회하지 않는다.
* Context에 없는 동작을 추측해서 구현하지 않는다.
* 필요한 새로운 규칙은 해당 Context 문서에 먼저 정의하고 구현한다.
* 실제 인게임 동작과 구현 결과가 다르면 Scenarios를 기준으로 원인을 확인한다.
* 기존 캐릭터가 정상적으로 동작하는 공통 시스템을 신규 캐릭터 하나 때문에 변경하지 않는다.
* 신규 기능은 가능한 한 재사용 가능한 공통 로직으로 구현한다.
* scenarios 폴더의 시나리오들의 변수등은 타 프로젝트에서 구현된 것을 가져온 것이므로 변수등이 완벽히 일하지 않으며 프로젝트 기준으로 반드시 변환하여 사용한다.

**핵심 원칙: Context가 시스템의 설계 문서이며, 캐릭터 구현은 Context의 규칙을 따르는 방식으로 이루어져야 한다.**
